# 작업종료

현재 브랜치의 변경사항을 커밋하고, main에 병합한 뒤 remote에 푸시한다.

## 실행 순서

다음 단계를 순서대로 수행한다. 각 단계에서 오류가 발생하면 즉시 멈추고 사용자에게 알린다.

### 1단계 — 현재 상태 파악

아래 명령을 병렬로 실행한다.
- `git branch --show-current` — 현재 브랜치 이름 확인
- `git status` — 변경된 파일 목록 확인
- `git diff --stat` — 변경 내용 요약 확인

현재 브랜치가 `main`이면 **중단**하고 사용자에게 "현재 main 브랜치입니다. 날짜 브랜치에서 작업해주세요."라고 알린다.

### 2단계 — 커밋 메시지 결정

`CHANGELOG.md`를 읽고 `## [미커밋]` 섹션 아래의 항목들을 커밋 메시지 본문으로 사용한다.

- `[미커밋]` 섹션에 항목이 없으면 `git diff --stat`를 기반으로 한 줄짜리 요약을 메시지로 사용한다.
- 커밋 메시지 형식: `[미커밋]` 섹션의 항목들을 그대로 사용한다 (첫 줄은 항목들의 공통 주제를 한 줄로 요약).

### 3단계 — 커밋

변경된 파일 전체를 스테이징하고 커밋한다.

```
git add -A
git commit -m "<커밋 메시지>"
```

커밋 트레일러: `Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>`

커밋 성공 후, `CHANGELOG.md`의 `## [미커밋]` 헤더를 `## YYYY-MM-DD | <커밋 해시 7자리>` 형식으로 교체하고, 빈 `## [미커밋]` 섹션을 파일 맨 위에 새로 추가한다. 이 변경은 **별도 커밋 없이** 다음 작업을 위한 준비 상태로 남긴다. CHANGELOG 정리 자체는 커밋하지 않는다.

### 4단계 — main 병합

```
git checkout main
git merge --no-ff <작업 브랜치> -m "Merge branch '<작업 브랜치>' into main"
```

### 5단계 — remote 푸시

```
git push origin main
```

푸시 완료 후 사용자에게 완료 메시지를 출력한다:
- 커밋 해시
- 병합된 브랜치 이름
- 푸시된 remote URL (있으면)
